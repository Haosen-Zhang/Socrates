# P05 local execution records

`FlightRecorderService` is a read-only projection owner. It does not dispatch, resume tools, mutate ledger facts, or interpret checkpoint state as audit history. Migration 029 adds projection rows, source cursors, retention policy and tombstones. Existing EventStore/ExecutionEventStore, room command events, invocation ledger, verification facts, routing decisions, attempts and approval facts remain authoritative. ExecutionEventStore persists in `runtime_events` (migration 017), not a separate table.

Production mounting: `/flight-recorder/rooms/:roomId`, export preview, read-only diagnostic import, and retention mutation. The task/project UI receives room/task identity and guards asynchronous reads with abort on navigation. It displays timeline or parent relationships, stage/member/failure/search/amount filters, paged records, known and estimated cost stages separately, selected event metadata, diagnostic preview/download and retention. Related-action callbacks open the original task room; they do not introduce another retry owner.

Task ownership resolves command run/task IDs, ledger run IDs and adaptive child IDs to the original root. Source sequence numbers retain each source's ordering; projection sequence is arrival/index order, not a claim of universal wall-clock order. Parent links provide causality. EventStore ingestion is incremental. A SQLite change revision avoids scanning unchanged state; mutable source refresh is bounded to 5,000 records per source and explicitly marks possible partial history. This first release does not promise unbounded historical reconstruction or a global cross-source sequence.

Actual reuse: installed `@opentelemetry/sdk-trace-base` **2.6.0**, Apache-2.0, and existing `@opentelemetry/api`. Inspected installed `BasicTracerProvider` implementation and license. `BasicTracerProvider`, `SimpleSpanProcessor`, SDK span context and parent context run in the production projector. A deterministic SDK ID generator makes persisted parent/child mappings stable; tests inspect real InMemorySpanExporter spans, including equality of child parent IDs to the actual root span ID. The SDK has no global registration, automatic instrumentation or network exporter. An optional standard SpanExporter can be supplied by the host; no hand-written remote transport exists. A public remote-exporter configuration UI is not enabled in this release.

Only allowlisted structural fields cross the projection/export boundary. Raw prompts, reasoning, error prose, tool inputs/outputs, filenames, headers and environment variables never enter the new projection. Known token/cache counts, IDs, status, price references and artifact hashes can be retained. This does not retroactively sanitize existing business stores; their original retention/access policies still apply. Deep capture is deliberately unavailable rather than silently enabled. Imports validate bounded JSON and return a separately labelled read-only view with the same field filtering; they neither persist foreign commands nor run them.

Diagnostics include schema/version, event JSONL, local IDs/parent relationships, cost summary, unknown-cost counts and declared field/capability scope. Full artifacts are excluded. Currency totals use bigint at the ledger's fixed scale. Stage totals include each invocation once; retries are an overlapping diagnostic dimension, not an extra total. The main cost summary reads the original ledger independently of trace retention. Metadata-only capture cannot prove repeated identical prompt text, so no repeated-context claim is shown. Per-page cost sorting is explicitly labelled as per-page.

Retention defaults to 30 days and 10,000 events, adjustable within bounds. Deleted projection IDs remain tombstoned so rereading mutable facts does not silently recreate expired records. Room deletion cascades the new tables. Trace cleanup does not delete cost or verification business evidence. UI reports expired/partial history and does not claim exported artifact hashes imply artifact bytes remain available.

Validation: `bun test apps/sidecar/src/services/flight-recorder.test.ts` exercises real SQLite/EventStore, real OTel spans and complete controlled Native and Team command entry points: secret injection/persistence/export, room separation, repeat projection/export without additional tool/model calls or charges, real invocation/price references, Team root ownership, retention, parent-span identity, filter-before-pagination, and inert import. Full application/type/browser gate results belong in implementation-progress.md. No paid provider or private workspace was accessed.
