# 成本感知 Work 使用指南

## 选择执行方式

在 Work 房间选择 Economy（经济）、Balanced（平衡）、Quality（质量）或 Custom（自定义）。前三种按任务特征、可用成员、能力和预计整个流程的费用选择方案；小任务可能只启动一个执行成员，即使房间有多人。Quality 仍受预算和权限限制。Custom 固定直接执行或团队及成员；显式成员选择是硬约束，失败不会被当作自动更换成员的许可。

先检查推荐分工、费用区间和验收条件，再提交。团队计划需要批准时，打开任务的计划面板；批准只覆盖显示的文件、命令和成员范围。扩大范围、换成员或升级时按界面重新确认。成员不足、缺凭证、不支持工具或无法报价时，先修正配置；不要把普通 @ 文本当调度命令。

## 预算与费用

任务预算限制后续请求的准入，不是供应商最终账单担保。Soft 使用估计输入和输出上限做预留；Strict 需要可信的单次费用上界，条件不足会拒绝准入。已经发到供应商的请求无法撤回消费。预算不足时暂停，查看已有产物与阻止原因，加额后使用原任务恢复入口，避免重新提交同一任务。

“已计价”来自有用量和冻结价格的调用；“预留”是尚未结算的准入额度；“估算”使用可编辑参考或预设价格；“未知/待对账”表示费用或远端结果仍不确定。不同币种分列，不自动换汇。代理端点同名模型不能证明同价；未列模型的预设只是估计，可在供应商设置确认价格。历史费用保留当时的价格快照，不因今天修改价格、取消任务或回退对话而退款。

请求发送后断线，系统保留可能发生的消费，不自动释放预留或重发副作用。先核对任务和供应商账单，再使用界面提供的对账/恢复操作。不要用删除数据库解决预算暂停。

## 什么算通过验证

`verified_success` 表示配置的必要机器检查在对应产物版本上通过。模型或审核成员说“通过”不是机器证据；执行完成但没有计划、旧历史或需要人工判断的结果仍是未验证。检查失败、证据缺失和产物随后变化会分别显示失败、不确定或失效。

打开验收面板查看检查、命令退出结果、日志、产物哈希与版本。文件/JSON 断言只证明声明的条件，不证明研究事实、审美质量或所有潜在错误。检查失败时修复后重新运行，不降低测试标准来取得通过状态。

## 数据可以发给哪些 Provider

项目记忆页可以为每条记忆限制允许的 Provider；只有确认、仍有效且授权的条目进入请求。撤销、过期、来源删除和显式冲突会阻止后续使用。已启动任务冻结版本，新加入记忆不会悄悄进入旧任务；显式刷新会形成新的上下文版本。

此限制针对记忆条目，并不是整个工作区的通用数据防泄漏开关。任务本身的文件和提示仍按房间成员、当前 Provider、工作区及工具授权处理。若项目只允许特定 Provider，先只把这些 Provider 的成员加入 Work 房间和许可池；不要把机密文本交给未批准成员。Chat 必须显式选择来源项目和条目共享，且不会因此获得工具权限。

## 管理与导出

项目 → Memory：创建或从来源提出条目，检查来源后确认；可以搜索、编辑、查看版本、撤销、导入及导出。导入内容先成为待确认条目，不能改变预算、权限或角色。确认冲突要先解决，不能让互相矛盾的要求同时成为有效约束。

项目 → Tasks → 任务详情 → Execution record：按阶段、成员、失败或金额查看记录。可预览诊断包后下载，再以只读方式导入查看。默认仅元数据，排除原始提示、思考正文和文件内容；导出不执行工具、不新增模型费用。保留期/条数清理只影响记录投影，不删除业务账本。当前不提供远程上传设置或原文深度捕获。

## Arena 对比实验

项目 → Arena，选择来源房间、主要/对照/审核成员、任务、明确的起始文件、共同验收条件及总预算。界面模板是四组各一次：A 主要成员直接执行，B 对照成员直接执行，C 规划加执行，D 再加独立审核。后端批量配置可增加任务与重复，预检应先核对总样本数和费用。点击运行才会调度；真实模型会使用已配置 API 并消费费用，受控示例与真实实验标签分开。

每组使用独立文件副本和记忆快照，原项目不作为实验写入目标；外部副作用工具和受保护验收定义不可通过普通批准解禁。需要计划/工具审批时进入该样本房间处理，再恢复实验。可以停止单样本或实验；已消费费用保留。关闭应用后不会自动重跑完成样本。

结果查看通过率、每个验证成功费用、原始样本、时间及未知费用。失败、取消和预算不足不会从分母消失；零通过或未知费用不能当作免费成功。重复同一任务不等于更多独立任务，少量模拟结果不能推荐某模型或声称省钱。

先看差异、选择文件并确认，才将实验产物应用到原项目；原文件已变则停止。当前支持有限大小的声明 UTF-8 文件，不自动应用二进制或删除。策略建议也需要足够证据和明确确认，并保留可回滚版本。清理只删除该实验的隔离产物，费用和历史引用仍保留，过期产物不能再读取或应用。

## 升级与恢复

升级前退出应用并保留完整数据目录及工作区备份。程序在已有数据库需要迁移时先创建一致 SQLite 备份（数据库旁 `.backup-时间`）。恢复时退出所有应用/sidecar，保留当前数据库及 WAL/SHM，再用匹配版本程序打开独立恢复副本核对房间、历史和待处理任务；不要在运行中覆盖数据库。

不支持反向 schema 迁移。旧程序不能识别新 schema 时应拒绝打开，不能通过删除迁移记录绕过。数据库备份不包含所有外部工作区文件或系统 Keychain；分别保存。升级、备份和恢复测试使用临时副本，不应直接试验用户的唯一数据。

维护者可在启动 sidecar 时设置 `SOCRATES_AUTOMATIC_ADMISSION_ENABLED=false`，仅关闭新自动任务准入；原任务幂等查询、加额和恢复保留。`SOCRATES_ARENA_ADMISSION_ENABLED=false` 仅关闭新实验准备，已经准备的实验可继续。默认开启；这是维护控制，不是删除任务或撤销已发请求。工作流版本不兼容时保留记录并拒绝恢复/批准，需用匹配版本打开；当前没有自动跨版本转换器。
