# P06 project memory

ProjectMemoryService owns append-only entry versions, project-scoped search, explicit Chat sharing, frozen task snapshots and Provider manifests. Migration 030 adds these records without rewriting rooms/history. SQLite FTS5 unicode61 is actually queried for search, with a bounded literal Chinese substring fallback inside the selected project. Existing Zod validates exchange input. No embedding service or extraction model is installed or called.

The Work project Memory page creates proposed entries, edits versions, confirms/rejects batches, pins/deactivates entries, records explicit conflicts, chooses provider access, previews/imports JSON and reads version history. It can propose source quotations from existing messages and historical artifact references from actual passed verification records. These local proposals never become confirmed automatically. Task manifest selection and explicit stopped-task refresh are available; refresh creates a distinct snapshot requiring replanning and never mutates a running task's context. Chat has an explicit Work-room/entry picker and revoke control; no workspace tools are granted.

RoomCommandService freezes entry versions and message cursor before child dispatch. ModelInvocationBroker derives a provider-specific manifest from that snapshot and accounts for the added context before cost admission. Both actual Gateway and Native AI SDK payloads receive the bounded, explicitly untrusted background. Each request rechecks current entry status, sharing scope, provider restrictions, expiry and source availability. Newly confirmed entries do not enter an already-started task, including another provider's later call. Revocation suppresses previously selected content; the original manifest remains historical evidence. EventStore records only IDs/versions/exclusion counts for Flight Recorder.

Manifests retain the frozen memory revision, task cursor, provider identity, selected entry versions/sources/reasons, conservative byte-based token estimate and omitted counts. Pinned constraints rank first, then constraints and query relevance. A clean matching Git HEAD is required for revision-bound facts; dirty/unknown revisions are excluded. Both sides of explicitly declared confirmed conflicts are excluded until the user resolves them. This version does not claim semantic contradiction detection.

Versioned JSON export includes entry versions, content hashes and historical portable provenance. Unresolvable local references are represented by kind/hash summaries instead of private paths. Import has byte/count/depth/schema checks, rejects secret-like material and absolute user paths, and always creates proposed unpinned entries. Fingerprinted imports are idempotent. Markdown is a readable snapshot through the markdown endpoint. Imported instructions remain data and cannot change tools, budgets or roles. Arena captures only explicitly selected current project-wide entries and clones them into a new isolated project retaining provider policies; it does not subscribe to later production-memory updates.
