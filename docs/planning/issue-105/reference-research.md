# Issue #105 reference research

Research snapshot: 2026-08-01. Sources are repository code, repository/package metadata, and official documentation only. Repository links below are pinned to the inspected commits where source details matter.

## Executive recommendation

Use a small Socrates-owned dock and data model. For the file explorer, flatten the expanded directory state into visible rows and virtualize those rows with [`@tanstack/react-virtual`](https://www.npmjs.com/package/@tanstack/react-virtual); do not add a full tree framework. For diffs, first spike [`@git-diff-view/react`](https://www.npmjs.com/package/@git-diff-view/react) behind a local `DiffView` seam, using its unified/split modes. If its syntax-highlighting/CSS bundle or CSP behavior is unacceptable, keep the same seam and fall back to a small unified-only renderer using sidecar-produced parsed hunks.

All filesystem and Git work should stay in the existing sidecar. Add room/workspace-scoped read endpoints that construct `WorkspacePathPolicy` from the stored canonical workspace, return workspace-relative paths only, apply explicit entry/depth/byte/time limits, and never expose an arbitrary `cwd` or command. Keep `.git`, secret paths, symlinks and hardlinks behind the existing policy. Git invocation should disable hooks, external diff/textconv and executable filters. The desktop should receive inert tree/diff data, not filesystem authority. This preserves Issue #105's no-approval read path and avoids a second runtime/tool protocol.

## Primary implementations

### openai/codex

- **What is actually public:** the inspected repository is primarily a Rust CLI/TUI plus an app-server protocol; it does **not** contain the proprietary Codex desktop right-side workspace/file dock. Therefore its interaction/layout may inspire Socrates, but there is no public React panel to copy.
- **Diff acquisition:** [`codex-rs/tui/src/get_git_diff.rs`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/codex-rs/tui/src/get_git_diff.rs) checks for a work tree, gets tracked changes and separately synthesizes diffs for untracked files. It bounds each workspace command, disables hooks, passes `--no-textconv`, `--no-ext-diff`, and neutralizes executable clean/process filters. These are directly useful security patterns for Socrates' sidecar implementation.
- **Diff model/rendering:** [`codex-rs/tui/src/diff_model.rs`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/codex-rs/tui/src/diff_model.rs) separates add/delete/update data; [`codex-rs/tui/src/diff_render.rs`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/codex-rs/tui/src/diff_render.rs) parses/render hunks with line numbers, add/delete gutters, wrapping, syntax highlighting and bounded highlighting. Dependencies are Rust `diffy`, `ratatui`, and `syntect`, so this renderer is not reusable in the React/Tauri frontend without a rewrite.
- **Service boundary:** [`codex-rs/app-server-protocol/src/protocol/v1.rs`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/codex-rs/app-server-protocol/src/protocol/v1.rs) and [`codex-rs/app-server/src/request_processors/git_processor.rs`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/codex-rs/app-server/src/request_processors/git_processor.rs) keep Git work behind a typed request/response boundary. The architectural pattern is reusable; Socrates should implement it through its existing Hono sidecar routes, not adopt Codex's protocol.
- **License:** Apache-2.0 ([repository `LICENSE`](https://github.com/openai/codex/blob/ee0247f95a6fe2b094ba2253d82cae2a2b4c2dff/LICENSE)). Code may be adapted with Apache notice/attribution obligations, but a clean TypeScript implementation of the command-hardening ideas is cheaper.

### esengine/DeepSeek-Reasonix

- **Closest UI reference:** [`desktop/frontend/src/components/WorkspacePanel.tsx`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/desktop/frontend/src/components/WorkspacePanel.tsx) is a real React workspace panel. It switches file/changed views, lazily loads directories, flattens open nodes, virtualizes visible rows with `@tanstack/react-virtual`, preserves selection/open-directory state, displays explicit Git warnings, and guards stale async responses with scope/request IDs. This is the strongest interaction and state-management inspiration.
- **Diff UI:** [`desktop/frontend/src/components/editors/HljsDiff.tsx`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/desktop/frontend/src/components/editors/HljsDiff.tsx) renders old/new line numbers and +/- gutters, uses highlight.js output, and virtualizes after 200 rows. [`desktop/frontend/src/components/DiffView.tsx`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/desktop/frontend/src/components/DiffView.tsx) provides a useful replaceable renderer seam.
- **Backend boundary:** [`desktop/workspace_changes.go`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/desktop/workspace_changes.go) gathers status/change detail behind Wails methods, scopes requests to a tab workspace, merges session and Git changes, and caps decoded/rendered change detail at 2 MiB. Socrates should copy the boundary/limits concept, not the Wails API or direct filesystem implementation.
- **Dependencies:** the frontend declares React 19, `@tanstack/react-virtual`, `highlight.js`, and Wails bindings in [`desktop/frontend/package.json`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/desktop/frontend/package.json). Its panel is large and product-specific; wholesale copying would import substantial tab/history/editor complexity. Copying small MIT-licensed helpers is legally possible, but reproducing the simple flattening/state pattern is lower cost.
- **License:** MIT ([repository `LICENSE`](https://github.com/esengine/DeepSeek-Reasonix/blob/37d18c872b84e9b99a5dce5c85fada14efd09279/LICENSE)); copied substantial portions require retaining the copyright/license notice.

### xai-org/grok-build

- **What is actually public:** Grok Build is a Rust full-screen TUI, not a React project-explorer application ([official repository layout](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/README.md#repository-layout)). No reusable desktop/right-dock project explorer was found in the inspected source.
- **File-tree pattern:** [`crates/codegen/xai-grok-workspace/src/file_system/file_tree.rs`](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/crates/codegen/xai-grok-workspace/src/file_system/file_tree.rs) creates a bounded textual project overview for model context, not an interactive explorer. Useful ideas are stable sorting, no symlink following, same-filesystem traversal, Git-ignore handling, and independent character/depth/directory limits. It uses Rust `ignore`, `dashmap`, and Tokio.
- **Git/status pattern:** [`crates/codegen/xai-grok-workspace/src/file_system/git_status.rs`](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/crates/codegen/xai-grok-workspace/src/file_system/git_status.rs) runs bounded Git status work off the async thread and caps subprocess output. This is operational inspiration, not a diff API suitable for Socrates.
- **Diff UI:** [`crates/codegen/xai-grok-pager/src/scrollback/blocks/tool/edit.rs`](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/crates/codegen/xai-grok-pager/src/scrollback/blocks/tool/edit.rs) provides TUI edit-diff rendering with optional dual line numbers, hunk separators, syntax highlighting and explicit 2 MiB/50,000-line highlighting caps. It depends on `ratatui`, `similar`, and `syntect`; the presentation code would require a React rewrite.
- **License:** first-party code is Apache-2.0, while vendored/ported code keeps its original license ([`LICENSE`](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/LICENSE), [`THIRD-PARTY-NOTICES`](https://github.com/xai-org/grok-build/blob/a4221165824e5b1f5c4c10b7459f65e78dd6448d/THIRD-PARTY-NOTICES)). Do not copy a file until its provenance is checked; for Issue #105, use only the bounded-work/security ideas.

## Proposed Socrates shape

1. Add ordinary authenticated sidecar routes under the existing room/workspace API surface: lazy directory listing and working-tree change summary/detail. Resolve the room's workspace server-side; never accept an absolute root from the desktop.
2. Reuse [`apps/sidecar/src/workspace/path-policy.ts`](https://github.com/Haosen-Zhang/Socrates/blob/66f6b3c82c3866fe5b9a8194ae65c9b8cabdfcc4/apps/sidecar/src/workspace/path-policy.ts) for canonical containment, secret denial, symlink/hardlink defenses and bounded reads. Refactor/reuse the bounded walk concepts already in [`apps/sidecar/src/tools/read-only-builtins.ts`](https://github.com/Haosen-Zhang/Socrates/blob/66f6b3c82c3866fe5b9a8194ae65c9b8cabdfcc4/apps/sidecar/src/tools/read-only-builtins.ts), but expose typed entries (`name`, workspace-relative `path`, `kind`, optional child hint) rather than a recursive path array.
3. Run fixed-argument Git commands in the sidecar with the Codex hardening flags. Return explicit `invalid_workspace`, `not_git`, `empty`, `truncated`, and error states. Cap file count, patch bytes, per-file bytes and execution time; identify binary/submodule/rename cases rather than forcing text rendering.
4. Keep one desktop dock state (`closed | files | diff`) keyed by active room/workspace. Lazy-load nodes; flatten only expanded nodes; virtualize with `@tanstack/react-virtual`. Preserve native Socrates toolbar, icons, colors and focus behavior.
5. Hide the actions when no valid active-room workspace exists. Read routes bypass tool approval because they are product inspection APIs, but remain authenticated and policy-bounded. Test path traversal, symlink escape, secret omission, non-Git, untracked files, executable Git config, truncation, stale room switches, loading/error/empty states, mode switching and close behavior.

This approach copies no UI code from the references. It adopts compatible architectural and interaction patterns, adds one very small tree dependency, and confines the riskier diff dependency behind a replaceable seam.
